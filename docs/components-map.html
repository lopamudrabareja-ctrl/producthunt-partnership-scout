Human (Kavya) Our code External API Gemini Flash Database
  1. Kavya clicks "Find partners" with her chosen categories; the request reaches the backend. 1b: once a day Vercel Cron triggers the same flow with a refresh, so her first visit already shows saved, fresh results.
  2. Backend checks the database for a cached run under 10 minutes old.
  3. Cache miss: backend sends a GraphQL query to ProductHunt.
  4. ProductHunt returns live posts and makers from the last 7 days.
  5. Backend combines that data with Kavya's profile and the scoring weights, then scores and ranks in plain code (same input, same order).
  6. Only the top ~10 products go to Gemini, with Kavya's profile as context.
  7. Gemini Flash handles them in ONE batched call.
  8. Gemini returns strict JSON drafts (one-liner, angle, message).
  9. Drafts return to the backend, which merges them into the ranked list.
  10. Backend saves the run and the launches to Supabase.
  11. The ranked list is shown to Kavya.
  12. Kavya reviews, edits and sends herself; her status choice is saved to the database.
Why the human gate sits at the end: a wrong message sent automatically to a founder cannot be unsent. The tool drafts; Kavya decides and sends (Nine Checks 06, 07, 09; The Cut: no auto-send). Failure paths: ProductHunt error or rate limit shows the last cached run with a banner; Gemini failure still shows the ranked list without AI text; missing maker shows "see PH profile", never an invented name. Data privacy: only public ProductHunt data and Kavya's product blurb go to Gemini.
